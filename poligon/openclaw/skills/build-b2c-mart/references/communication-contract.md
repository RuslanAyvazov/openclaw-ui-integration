# Краткий сбор входного пакета

Не вести пошаговый опрос. Собирать все недостающие входы одним сообщением и не
спрашивать повторно уже полученное. Писать обычным текстом без блоков кода,
вводных фраз и описания внутренних модулей.

## Неполный пакет

```text
Пакет:
- S2T: получен — s2t.xlsx
- Формат: iceberg
- SQL-прототипы: 4 из 6
Не хватает: table_2/DML_arc.sql, table_3/DML_arc.sql.
```

Если нет S2T или не выбран формат:

```text
Пакет:
- S2T: не получен
- Формат: не выбран
- SQL-прототипы: расчёт пока невозможен
Не хватает: S2T.xlsx и выбора iceberg/parquet.
```

Сначала обязательно запустить автоматическое сопоставление SQL по полям STG.
Если оно сообщает, что один SQL одинаково подходит нескольким таблицам, задать
один вопрос со всеми неоднозначными файлами:

```text
Уточните соответствие «файл → таблица → inc/arc» для: a.sql, b.sql, c.sql.
```

## Полный пакет

```text
Пакет полный: таблиц — 3; SQL-прототипов — 6 из 6. Начинаю проверку.
```

После этой строки сразу запускать проверку. Не добавлять объяснение архитектуры,
перечень будущих модулей или дополнительные вопросы без необходимости.

Не выводить содержимое SQL и не готовить длинный текст до первого вызова
инструмента. Итоговый ответ должен содержать только результат проверки и пути к
`context_config.json` и `dm_res`.
